  • Built a Python automation pipeline for large-scale video processing and YouTube publishing, designed for 1,500+ uploads per day.
  • Implemented concurrent processing, rate-limit handling and retry logic to keep it reliable within API quotas.
  • Deployed and operated the system on a Linux VPS, with logging for monitoring and troubleshooting.

The project

A content automation system for a YouTube publishing operation. The team produced videos and soundtracks with AI tools; my job was to turn that into a hands-off pipeline that assembled and published each video. I designed and built it on my own.

How it works

  • Reads each job (video, audio track, title and metadata) from spreadsheets on Google Drive through the Drive API.
  • Merges video and audio with FFmpeg and prepares the final file.
  • Uploads through the YouTube Data API, using multiprocessing to run about five jobs in parallel while staying inside quota limits.
  • Queues failed uploads for automatic retry.
  • Writes status and results back to the sheet, so the team could run everything from a spreadsheet without touching code.

Reliability

Detailed logging plus a per-upload history made every job traceable, so failures could be found and fixed quickly. The system ran on a Hetzner Linux VPS.

Outcome

The pipeline was built for 1,500+ uploads per day, with headroom beyond that. I also raised early that the planned content volume risked breaching YouTube's API policies, which fed into the company's decision on the project's future.
